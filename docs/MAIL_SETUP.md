# Self-hosted mail (Mailcow) co-located with boop-agent

This is an **infrastructure** doc, not a feature of the bot. It describes how a Mailcow stack is deployed on the same VPS that runs `boop-agent` and a Traefik reverse proxy, without disrupting either. Use it as a reference for forks that want a similar small-footprint corporate mail server alongside their personal agent.

> **Credentials live outside the repo.** Admin password, mailbox passwords, SSH keys, and DKIM private keys are kept in the maintainer's password manager, not committed here. This file documents only operational procedure and structure.

## Why these decisions

| Decision | Reason |
|---|---|
| Mailcow (Docker compose) | Full SMTP/IMAP/web admin, single repo to clone, well-documented |
| Subdomain `mail.<domain>` (not the apex) | Keeps mail isolated; apex DNS stays free for app/API usage |
| Behind Traefik (HTTP routing only) | Reuses existing Let's Encrypt automation. Traefik is already on `:80/:443`. |
| SMTP/IMAP ports bound directly on host | Mail protocols don't multiplex over a single TCP port like HTTP — Traefik can't usefully proxy them |
| ClamAV disabled (`SKIP_CLAMD=y`) | Saves ~800 MB RAM on a 7-GiB VPS; corporate mail volume is too low for it to matter |
| IPv6 disabled in Mailcow | Enabling it requires updating `daemon.json` and restarting Docker, which would briefly disrupt `boop-agent` and other services. IPv4-only is fine for outbound deliverability when rDNS is set. |
| Self-hosted ACME (`SKIP_LETS_ENCRYPT=y`) | Traefik already issues the cert for the public-facing hostname; Mailcow's internal ACME would race for port 80 |

## Pre-flight (do before installing Mailcow)

1. **rDNS** — the VPS provider control panel must map the public IPv4 to `mail.<domain>`. **This is the most common cause of poor deliverability** and must be done before sending any mail. Most providers also require the matching A record to exist first.

2. **DNS records at the domain registrar** (e.g. Openprovider):

   | Name | Type | Value |
   |---|---|---|
   | `mail` | A | (VPS public IPv4) |
   | `@` (apex) | MX 10 | `mail.<domain>.` |
   | `@` (apex) | TXT | `v=spf1 mx ~all` |
   | `_dmarc` | TXT | `v=DMARC1; p=quarantine; rua=mailto:postmaster@<domain>; ruf=mailto:postmaster@<domain>; fo=1` |

   The DKIM record is generated by Mailcow itself (see step 5 below).

3. **Resource budget** — Mailcow with ClamAV off uses ~1.3 GiB RAM steady-state. Disk: pull pulls ~3 GiB of images plus a few GiB for mail data over time. Verify the VPS has the headroom before starting.

4. **Outbound port 25** — the VPS provider must allow outgoing TCP 25. Verify with:
   ```bash
   timeout 5 bash -c '</dev/tcp/gmail-smtp-in.l.google.com/25 && echo open || echo blocked'
   ```

## Install steps

These run as a non-root user with Docker group membership. Adjust paths if running as a different user.

### 1. Clone Mailcow

```bash
cd ~
git clone https://github.com/mailcow/mailcow-dockerized.git
cd mailcow-dockerized
ln -sf mailcow.conf .env
```

### 2. Patch `generate_config.sh` to skip the IPv6 controller

Mailcow's `configure_ipv6` step rewrites `/etc/docker/daemon.json` and restarts Docker, which would interrupt every other container on the host. Comment out the call:

```bash
sed -i.bak '/^configure_ipv6$/s|^|# (skipped: avoid docker daemon restart) #|' generate_config.sh
```

### 3. Generate `mailcow.conf`

```bash
MAILCOW_HOSTNAME=mail.<domain> \
MAILCOW_TZ=<your-tz>           \
MAILCOW_BRANCH=master          \
SKIP_CLAMD=y                   \
bash generate_config.sh < /dev/null
```

### 4. Edit `mailcow.conf` for the reverse-proxy and IPv6 setup

```bash
sed -i \
  -e 's/^HTTP_PORT=.*/HTTP_PORT=8480/'         \
  -e 's/^HTTP_BIND=.*/HTTP_BIND=127.0.0.1/'    \
  -e 's/^HTTPS_PORT=.*/HTTPS_PORT=8443/'       \
  -e 's/^HTTPS_BIND=.*/HTTPS_BIND=127.0.0.1/'  \
  -e 's/^HTTP_REDIRECT=.*/HTTP_REDIRECT=n/'    \
  -e 's/^ENABLE_IPV6=.*/ENABLE_IPV6=false/'    \
  -e 's/^SKIP_LETS_ENCRYPT=.*/SKIP_LETS_ENCRYPT=y/' \
  -e 's/^DOCKER_COMPOSE_VERSION=.*/DOCKER_COMPOSE_VERSION=native/' \
  mailcow.conf
```

The HTTP/HTTPS ports are arbitrary — pick anything not already bound on the host. Both must be bound to `127.0.0.1` so only the local Traefik can reach them.

### 5. Add a Traefik override

Create `docker-compose.override.yml` in the Mailcow directory:

```yaml
services:
  nginx-mailcow:
    networks:
      mailcow-network:
        aliases:
          - nginx
      traefik-public: {}
    labels:
      - traefik.enable=true
      - traefik.docker.network=traefik-public
      # HTTPS — Traefik terminates Let's Encrypt
      - traefik.http.routers.mailcow.rule=Host(`mail.<domain>`)
      - traefik.http.routers.mailcow.entrypoints=websecure
      - traefik.http.routers.mailcow.tls=true
      - traefik.http.routers.mailcow.tls.certresolver=letsencrypt
      - traefik.http.routers.mailcow.service=mailcow
      - traefik.http.services.mailcow.loadbalancer.server.port=8480
      # HTTP -> permanent redirect to HTTPS
      - traefik.http.routers.mailcow-http.rule=Host(`mail.<domain>`)
      - traefik.http.routers.mailcow-http.entrypoints=web
      - traefik.http.routers.mailcow-http.middlewares=mailcow-https-redirect
      - traefik.http.middlewares.mailcow-https-redirect.redirectscheme.scheme=https
      - traefik.http.middlewares.mailcow-https-redirect.redirectscheme.permanent=true

networks:
  traefik-public:
    external: true
```

Replace `mail.<domain>`, `letsencrypt`, and `traefik-public` with the names that match your existing Traefik setup.

### 6. Pull, start, and verify

```bash
docker compose pull       # ~3 GiB
docker compose up -d
docker compose ps         # all should be Up
curl -I https://mail.<domain>/   # expect HTTP/2 200 with valid LE cert
```

### 7. First-time admin login

Mailcow ships with `admin` / `moohoo`. Log in once and immediately rotate the password from **System → Configuration → Access**, or non-interactively:

```bash
./helper-scripts/mailcow-reset-admin.sh -y
```

(Prints a fresh random password.)

### 8. Add the domain and read the DKIM TXT record

Through the admin UI: **Email → Configuration → Domains → Add domain**, then **Configuration → ARC/DKIM keys**. Or via the API once a session cookie or API key exists:

```bash
curl -b $COOKIES -X POST -H 'Content-Type: application/json' \
  https://mail.<domain>/api/v1/add/domain \
  -d '{"domain":"<domain>","aliases":100,"mailboxes":50,"defquota":1024,"maxquota":10240,"quota":51200,"active":1,"rl_frame":"s","restart_sogo":1}'

curl -b $COOKIES https://mail.<domain>/api/v1/get/dkim/<domain>
```

Add the `dkim_txt` value as a TXT record at `dkim._domainkey.<domain>` in the registrar.

### 9. Deliverability smoke test

```bash
TEST_ID=test-$(openssl rand -hex 6)
# send mail from the new mailbox to test-XXXX@srv1.mail-tester.com
# then visit https://www.mail-tester.com/$TEST_ID
```

Target score: 9–10/10. Anything below 8 means a DNS record is wrong.

## What's left for the operator

These are out of scope for the initial setup but worth knowing:

- **Spamhaus DQS API key** (free) for inbound spam filtering — many cloud-provider IPs (including OVH) are excluded from the public Spamhaus DNSBLs. Sign up at <https://www.spamhaus.com/free-trial/>, then put the key in `mailcow.conf` as `SPAMHAUS_DQS_KEY=...`.
- **Backups** — Mailcow ships `helper-scripts/backup_and_restore.sh`. Schedule it.
- **Updates** — `./update.sh` periodically. After each update, re-apply the `configure_ipv6` patch from step 2 if `generate_config.sh` was overwritten.
- **2FA on the admin account** — set up TOTP from System → Configuration → Access.
- **Tighter SPF (`-all` instead of `~all`)** — once you're sure no other system sends mail as `<domain>`.

## Operations cheat sheet

```bash
# inside ~/mailcow-dockerized
docker compose ps                           # status
docker compose logs -f nginx-mailcow        # tail logs of one service
docker compose restart                      # graceful restart of the whole stack
docker compose exec postfix-mailcow postqueue -p   # mail queue
./helper-scripts/backup_and_restore.sh backup all  # backup
./update.sh                                 # update Mailcow (re-apply IPv6 patch after)
```

## Co-existence with `boop-agent`

The Mailcow stack lives in `~/mailcow-dockerized` (its own Docker compose project). `boop-agent` is unaffected because:

- Mailcow does **not** touch `/etc/docker/daemon.json` (the IPv6 patch above prevents it).
- Mailcow's `nginx-mailcow` container is added to the existing `traefik-public` external network — Traefik's labels are read from the running container, no Traefik restart needed.
- Host port conflicts are avoided: Mailcow uses `127.0.0.1:8480/8443` for HTTP/HTTPS and the standard `:25/:465/:587/:110/:143/:993/:995` for mail protocols.

After install, verify other containers are still healthy:

```bash
docker ps --format '{{.Names}}\t{{.Status}}' | grep -v mailcowdockerized
```
